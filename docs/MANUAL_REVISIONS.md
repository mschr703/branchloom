# Manuelle Zwischenänderungen

Der Kartendialog kann eine ausdrücklich ausgewählte, geänderte Zieldatei als **manuelle Revision** in der lokalen Branchloom-Datenbank festhalten. Das ist eine bewusste Zuordnung durch den Nutzer, keine aus Zeitstempeln abgeleitete Urheberschaft. Grundlage, manuelle Fassung und committierte Fassung des Karten-Worktrees werden mit Git dreifach verglichen.

## Ablauf

1. Öffne eine Karte mit gespeichertem Git-Worktree. Ändere eine bereits versionierte Textdatei im Ziel-Checkout, während der Karten-Worktree getrennt bleibt. Das Festhalten ist auch während eines laufenden Agenten möglich; für die spätere Übernahme muss dessen Dateifassung committiert und der Worktree sauber sein.
2. Unter **Manuelle Zwischenänderungen** wähle die Datei und **Änderung festhalten**. Branchloom speichert die Fassung, ihren SHA-256-Wert, den Zielbranch samt HEAD und die gemeinsame Git-Basis lokal. Die Auswahl beweist nicht, wer die Datei bearbeitet hat.
3. Öffne den Dreifachvergleich. Die Ansicht zeigt die gemeinsame Basis, die festgehaltene manuelle Fassung, den aktuellen **committierten** Agentenstand und das Ergebnis von `git merge-file --diff3`. Für jeden von Git markierten Konfliktblock stehen Basis und beide Varianten direkt nebeneinander. Wähle ausdrücklich **Manuelle Fassung** oder **Agentenfassung**, oder öffne **Eigene Fassung schreiben**, bearbeite den Text dieses Blocks und speichere die Auswahl. Der Text im Editor ist bis zum Speichern nur ein Entwurf; solange der Editor offen ist, kann die Datei nicht geschrieben werden. Jede gespeicherte Entscheidung bleibt mit Zeitpunkt in der lokalen Datenbank für genau diese Vorschau erhalten und ist nach einem Neustart wieder sichtbar. Konfliktfreie Teile außerhalb dieser Blöcke bleiben aus beiden Seiten erhalten.
4. Prüfe das vollständig entschiedene Ergebnis und wähle **Diese Datei zusammengeführt schreiben**. Der Hauptprozess prüft Zielbranch und -HEAD, Agenten-HEAD, gemeinsame Basis, den ursprünglichen Datei-Hash, das Vorschautoken und die gewählten Konfliktentscheidungen erneut; unmittelbar vor dem Ersetzen prüft er Datei und Git-Zustand nochmals. Nur die gewählte Zieldatei wird ersetzt. Ändert sich eine Quelle, eine Auswahl oder die Datei zwischen Vorschau und Klick, wird die Übernahme abgewiesen und ein neuer Vergleich nötig.

Der Ziel-Checkout ist nach dem Schreiben **absichtlich uncommittet**. Die G02-Integrationswarteschlange bleibt dadurch gesperrt; Branchloom führt keinen Git-Branch-Merge, Commit oder Rebase aus. Diese Stufe schützt und kombiniert eine Datei, sie integriert noch keine ganze Karte. Für eine spätere Branch-Übernahme sind getrennte Git-Prüfung, Commit/Abgleich und erneute Tests nötig.

## Gezielte Abnahme

`node scripts/smoke-electron.mjs --f03 --timeout-ms 180000` startet eine isolierte Quell-App mit synthetischem Git-Projekt. Der sichtbare Kartenablauf erfasst eine manuelle Revision, schreibt konfliktfreie Änderungen beider Seiten, zeigt bei einer zweiten Karte Basis und beide Varianten, verlangt eine Wahl und findet sie nach einem Renderer-Neuladen wieder. Anschließend wird ein Konfliktblock im Textfeld bearbeitet und die eigene Fassung nach erneutem Renderer-Neuladen wieder geöffnet. Eine spätere Zieländerung wird beim Schreiben abgewiesen; die neuere Datei bleibt erhalten und kann frisch erfasst werden. Die Main-Tests öffnen die SQLite-Datei nach dem Schließen erneut und prüfen so die dauerhafte Speicherung. Der Electron-Smoke prüft ein Renderer-Neuladen, keinen vollständigen App-Neustart.

## Grenzen

- Zugelassen sind bestehende, geänderte, versionierte UTF-8-Dateien bis 128 KiB ohne BOM. Gelöschte, unversionierte, binäre und symbolisch verlinkte Dateien bleiben ausgenommen. Änderungen im Karten-Worktree müssen vor dem Vergleich committiert sein.
- Eine Auswahl oder eigene Fassung gilt für genau einen von Git erkannten Konfliktblock. Eigene Fassungen sind auf 32 KiB gültigen UTF-8-Text je Block begrenzt; die gesamte Zieldatei bleibt auf 128 KiB begrenzt. Der Editor bearbeitet Text, keine visuellen Eigenschaften oder Dateistruktur außerhalb des Blocks.
- Konfliktentscheidungen hängen an der konkreten Vorschau. Ändern sich Agenten-Commit, Basis, Ziel-HEAD oder Zieldatei, wird ein alter Vergleich nicht mehr angewendet. Für die neue Quellenlage ist eine neue Revision nötig.
- Der Vergleich ist eine Momentaufnahme. Auch nach der zweiten Hash-Prüfung kann eine externe Anwendung theoretisch im kurzen Fenster vor dem atomaren Ersetzen schreiben. Branchloom hält seine eigenen Schreibaktionen über eine SQLite-Sperre auseinander, kann aber fremde Editoren nicht sperren. Bei gleichzeitiger Bearbeitung die Änderung zuerst im Editor abschließen und danach frisch vergleichen.
- Die Revision und der Textinhalt liegen nur in der lokalen SQLite-Datei, nicht im öffentlichen Repository. Sie enthalten möglicherweise Projektinhalte und gehören nicht in einen öffentlichen Export oder Commit.
