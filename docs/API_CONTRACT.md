# Shared API contract (F02)

In **Agents → Shared API contract**, define one `GET /api/...` endpoint for the active project. The response is one object or a list of objects, each with 1–16 flat string, number, or boolean fields and required flags. One error case specifies an HTTP status, code, and message. This deliberately narrow format is the supported contract, not arbitrary JSON Schema or OpenAPI.

1. Edit the route, fields, and error case. **Preview** validates the draft and shows deterministic local success and error JSON examples. It does not write to the database.
2. **Save revision** persists the exact normalized draft and SHA-256 fingerprint. A stale preview cannot overwrite a newer revision. Older revisions remain visible.
3. **Connect** both the frontend and backend cards. Each new agent launch receives the same revision and fingerprint in its prompt, and the launch evidence labels the contract as a source. A card with an older binding is blocked from starting until explicitly rebound. Changing a card binding is rejected while its agent runs or if the card changed since the UI loaded.
4. Paste a response and HTTP status into **Check response**. The local checker reports field paths, expected types, and actual types. It checks both success and the configured error case without a network request or storing the response text.
5. Under **Local mock and endpoint check**, click **Start mock** to serve the saved revision's synthetic success example at `http://127.0.0.1:<random-port>/api/...`. Add `?case=error` for the configured error example. The server binds only to IPv4 loopback, accepts only the selected GET path, and stops on click, app exit, or a new saved revision. The mock is not restored after restart. Local browser origins can read its synthetic responses; remote origins are rejected.
6. Enter a local server origin such as `http://127.0.0.1:3000` and click **Check endpoint now**. Branchloom appends the saved route and sends one GET request. It does not follow redirects or send credentials. Only a literal IPv4 loopback origin with an explicit port is accepted. The check has a five-second timeout, 32 KB response limit and the existing 100-item schema limit. A failed connection has no claimed HTTP status. A returned response is checked for status, JSON shape, field names and types. Exact mismatches appear under the controls.

A saved revision is project-local. Cards in other projects cannot be connected to it. A resumed Codex conversation is allowed only when the card still has the same contract revision it received at its original start. Endpoint checks save only the requested local URL, time, revision/fingerprint, received HTTP status if any, and bounded mismatches. They never save the response body. The most recent 200 checks per project are retained; the UI shows the latest 20. After a new revision, retained older checks appear as **stale** and the old mock no longer serves its previous example. A passing live check proves only that one local response matched that revision at the recorded time; it does not prove the implementation, repeated behavior, or a particular Git commit. There is no automatic polling, nested schema, agent-generated contract proposal, or canvas link yet.
