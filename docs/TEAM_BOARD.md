# Shared project board for guests

Branchloom can issue a short-lived link to a view of one local project's board. The host stays in control of the project and its agents. Links are read-only by default; an optional permission lets a guest comment on cards. This is an early cooperation step, not a synchronized team workspace.

## Try it

1. Open a project, then its project settings and **Projektboard teilen**.
2. Enter a guest name. The default invitation is read-only. To let that guest send short comments on cards, explicitly select **Diesem Gast Kartenkommentare erlauben** before creating the link. Choose **Auf diesem Gerät testen** for a local browser link, or **Tailscale-Link erstellen** for a peer on your tailnet. The latter requires a connected local Tailscale client and network permission for the peer to reach your device.
3. Inspect the board and its card titles before sending the link. Copy the new link; Branchloom shows the full secret only immediately after creation. Make a separate invitation for each guest.
4. The guest opens the link in a regular browser. The view refreshes every 15 seconds and also retries when the browser reports that it is back online. They can see the project name, columns, up to 200 active card titles and priorities, queue state, and which cards have a running session. A comment-enabled guest can send one short note from a visible card; the host sees it in the project's Decision Inbox, on that card, and under **Feedback der Gäste** in project settings. A read-only guest cannot post. Neither invitation changes cards or starts an agent.
5. Revoke an individual invitation in project settings when it is no longer needed. The guest page clears its board on its next refresh. Links expire after 24 hours; app restart also revokes them.

The local listener binds to `127.0.0.1` on an ephemeral port. The optional peer listener binds only to the active local Tailscale IPv4 address, not every network interface. It uses HTTP inside the tailnet connection. It does not configure Tailscale Serve or alter other network services. A copied URL contains a bearer secret: anyone who can reach that listener and has the URL can read the shared view until expiry or revocation. There is no verified Branchloom account identity or role system yet.

The guest board is a separate, limited projection. It does not include descriptions, paths, agent names, logs, credentials, other guests' comments, or host IPC. Obvious key-like text in a title is hidden, but arbitrary personal text in titles cannot be detected reliably; the host must inspect titles before sharing. A truncated marker appears when more than 200 active cards exist. Invitations are scoped to their project and stored as secret hashes in the local SQLite database. The running app keeps the issued secrets in a listener allowlist; no old link becomes valid on a later app run.

The optional comment POST is limited to 800 characters, an existing card in the invited project, a valid comment-enabled link, and the guest page's exact origin. A client request ID makes a retry return the first saved comment rather than adding another. If the browser loses the response, it leaves the draft visible and asks the guest to retry with that same ID. The project and all-project Decision Inbox show unread guest feedback in the **Prüfung** category. **Als gelesen markieren** clears only that inbox entry; the original remains on the card and in project settings. Archived cards no longer appear as open inbox sources. The host can view the latest 100 comments in project settings and all comments for an individual card; storage currently caps comments at 300 per project. Guest names are labels supplied by the host, not verified accounts. Comments have no edit or delete UI yet. A revoked or expired link cannot post, including a retry.

This does not synchronize board edits back from guests. Guests cannot edit cards, bring their own agents, resolve collisions, or merge. A three-window Electron smoke covered two viewers and one commenter, and an actual Tailscale-address listener smoke passed on the development machine; a remote second device and network-loss recovery remain unverified.
